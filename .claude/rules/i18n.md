# Interface Languages (ADR-070)

The interface follows the language picker in the menu bar: English, German,
French, Dutch and Spanish. There are no `/de/` URLs; pages keep their paths.

## Adding or changing a visible text

- English is the source and the key. `ui/src/messages/<lang>/<area>.json` maps
  each English text to its translation; `en/` maps every text to itself.
- Add a text in all five languages in the same commit. A missing language,
  a changed `{placeholder}` or an em dash fails
  `ui/__tests__/unit/lib/i18n-messages.test.ts`.
- Changing an English sentence orphans its translations: update the key in
  every language, not only in English.
- One area per group of pages (`nav`, `common`, `signin`, `catalog`,
  `jurisdictions`, `home`, `public`, `compliance`, `access`, `patient`,
  `research`, `holder`, `explore`, `admin`). A new area goes in every
  language folder and in `ui/src/messages/index.ts`.
- Client component: `const t = useT("area")`, then `t("Text")` or
  `t("{n} days", { n })`. A text with a link or bold part:
  `<T area="area" tags={{ a: <Link href="/x" /> }}>{"See the <a>register</a>."}</T>`.
- The i18n test checks every file that imports `@/lib/i18n/translate`, so
  a `t("...")` literal without an entry is caught. Labels a page takes from a
  library (`PURPOSE_LABELS`, `MEASURE_LABELS`) need a test that lists them.
- The step by step for a page, with its journey: the `translate-page` skill.
- Data values stay as they are: dataset titles, names, API error messages and
  the demo's prefilled form contents.

## Docs (ADR-071)

- **TSX pages**: areas `docsGuide` (`/docs/user-guide`), `docsDeveloper`
  (`/docs/developer/**`), `docsArchitecture` (`/docs/architecture`),
  `docsCommon` (docs index, section pages, roadmap, glossary chrome, the
  translation notes). All registered; never edit `ui/src/messages/index.ts`.
- **Published Markdown**: the translation of `docs/<path>` is
  `docs/i18n/<lang>/<path>`, frontmatter `source`, `sourceHash` (SHA-256 of
  the English file), `language`. Write the body, then
  `python3 scripts/gen-docs-content.py --stamp docs/i18n/<lang>/<path>` and
  `python3 scripts/gen-docs-content.py`. Keep relative links and image paths
  as in English; translate Mermaid inside the fences.
- **Stale**: an English edit makes the translation `stale` in
  `ui/src/content/published-docs-i18n.json`; the page says so. Update the
  translation, `--stamp`, regenerate. `--report-i18n` lists missing and stale.
- **Images**: a translated screenshot goes in
  `ui/public/images/{guide,screenshots}/<lang>/<same name>`; a translated
  diagram is `<name>.<lang>.svg` next to the English one. Then
  `python3 scripts/gen-localized-images.py`. Show docs images with
  `LocalizedImage` / `useLocalizedImageSrc`, never a bare `<img>`. Capture
  with `SCREENSHOT_LANG=<lang>`.
- **Charts in TSX**: `ui/src/content/diagrams/<id>.ts`, add a `de:` (etc.)
  key with the same node ids; draw with `localizedChart(id, lang)`.

## Terms

- Legal terms come from `ui/src/lib/i18n/ehds-terminology.json`, taken from
  the Official Journal in each language (FR and ES abbreviate EEDS; FR says
  "autorisation de traitement de données", DE "Datengenehmigung"). The test
  fails on a variant the Regulation does not use. The page
  `/docs/ehds/glossary` shows the list.
- A new term: add it to the JSON and run
  `python3 scripts/i18n/check-ehds-terminology.py`.
- A chip or badge with little room gets a short form in `nav` (#797); the full
  term goes in its `title` and wherever there is room.
