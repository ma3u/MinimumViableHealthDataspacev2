The problem

Two regimes of the European Health Data Space, and a person in the middle with paper

Primary use, Chapters II and III

The person's own data, their record, their doctor. A study or a specialist lab hands over results on paper or as a PDF. Nothing pushes them into the national patient record: only the provider who ordered a test may write it, and a cohort study is not treatment.

So the citizen is the only integration point that exists today.

Secondary use, Chapter IV

A researcher works under a data permit from a Health Data Access Body, with a citizen opt-out. Not consent. They need to find datasets across institutions, get the permit, agree terms with the holder, and analyse in a secure environment.

Every step needs the data to mean the same thing at both ends.

The platform is an open-source reference implementation of both regimes. The point I want to make first is the primary-use gap, because it is the one I live with. I am in a cardiovascular prevention study. The results reach me as PDF and paper. There is no API into the German ePA for an app like this, only listed digital health applications may write, so the person carrying their own data is the actual integration.

Primary use

Every value is checkable against the paper

LOINC, chosen by the unit

Lp(a) in mg/dL and in nmol/L are different measurements with different codes. The label never decides alone.

The range the laboratory printed

Verbatim, never normalised. A reference range is assay-specific.

Page and line

Where on the paper the number came from, so a clinician can verify rather than trust.

Nothing vanishes

Lines that matched no analyte and lines that could not be read are listed, never dropped.

This is the one screen a person compares with their own paper, so it carries the evidence. The conservation rule matters most: every printed row ends up coded, unmatched or unread.

Primary use · in a study

A trend across reports, and a published band beside the laboratory's own

One chart per measurement in one unit, across every report. A filled point came from a laboratory's document, a hollow one from a photograph.

The band is the guideline's where one names a threshold, and the laboratory's printed range everywhere else, named as such.

Every published range carries its source and a link. No source, no range. And no screen says normal, abnormal, or what to do.

For a study participant this is the value: results from the study centre, from the GP, from a gym scale, on one timeline. What the app adds is deliberately limited: a definition of the test, never an interpretation of the value. That is the medical-device line.

Secondary use

Analysis on OMOP, questions in plain language, grounded in the graph

A five-layer knowledge graph: dataspace, catalogue, FHIR R4, OMOP CDM, terminology. 127 synthetic patients, more than 5,300 nodes, every clinical node bound to SNOMED CT, LOINC, ICD-10 or RxNorm.

The model answers only from what the graph holds, and the graph holds what FHIR delivered. No code, no answer.

The natural-language layer is the AI part of the award. It is deliberately boring: a question becomes a graph query over standardised FHIR and OMOP nodes, and the answer cites the nodes. Grounding on a standard is what keeps it honest.

Stored once, in the cloud

Everything lands in one FHIR-based knowledge graph, five layers, every clinical node coded

A Neo4j graph on Azure Container Apps, persistent on Azure Files. FHIR R4 comes in as resources from a hospital's server or from the phone's bundle, and stays FHIR: Patient, Condition, Observation, MedicationRequest as nodes and relationships.

The FHIR-to-OMOP transform is one Cypher script over the same graph, so a person's Observation and its OMOP Measurement share the LOINC code node they are both coded by.

127 synthetic patients, more than 5,300 nodes. The moving dot is the path a lab value takes: Patient, Observation, its LOINC code, the OMOP Measurement, the OMOP Person.

What we found

Six findings from coding real sheets to FHIR and LOINC

The unit selects the code

The same label in two units is two measurements. Trusting the label alone put wrong codes on real values until the rule was made absolute.

Refusing is a feature

Both LOINC codes for RDW-SD are deprecated, so the value is carried unmatched rather than mis-coded. A wrong code is worse than no code.

LOINC names tests, not organisms

A stool report's 57 taxa have no LOINC term and never will. NCBI Taxonomy names them; the abundance stays a text code with the reason attached.

A printed range is assay-specific

It travels verbatim into referenceRange. Normalising it, or replacing it with a published band, destroys information a clinician needs.

Provenance must be first-class

Final versus preliminary, and the page and line, decided by the document and not its file extension. Marking a transcription final is the failure that matters.

Definition, not interpretation

The app says what a test measures, with a source. It never says what a person's value means. That line is the difference between an app and a medical device.

These came out of scanning real sheets, mine, and the test suites that grew around each mistake. The deprecated-code case is my favourite: the honest answer was to refuse.

What we need from the FHIR community

Five things that would make a citizen's own lab result first-class in FHIR

  1. An agreed extension for transcribed observations. Source kind, source line, page and box, recogniser confidence. We define ours; a shared one would let any receiver treat a scanned value with the right caution.
  2. A pattern for microbiome relative abundance. A text-only code with a data-absent-reason and a component carrying the NCBI Taxonomy entry under LOINC 41852-5. Is that the shape the community wants?
  3. LOINC terms consumer devices need. Visceral fat as a mass, the extracellular-to-total water ratio, remnant cholesterol, the triglyceride-to-HDL ratio.
  4. A citizen-upload profile in the EEHRxF laboratory result. What a person-submitted, possibly transcribed result must carry so a record system and a GP can read it with its provenance intact.
  5. FHIR-to-OMOP conventions for the uncoded case. Concept id 0 with the original code or label in the source value, mapped where the vocabulary lives.
These are asks, not complaints. Each one is a place where we had to decide alone and would rather have decided with you.
