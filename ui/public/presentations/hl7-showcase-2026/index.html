7:00. Both ends meet in one place. Everything is stored once, in one knowledge graph with five layers, and each layer is a standard. ▸ At the top, the dataspace: who takes part, the data product they offer, its policy, the permit, the contract and every transfer. ▸ Below it, the HealthDCAT-AP catalogue describes each dataset, so a researcher can find it. ▸ In the middle, the clinical data in FHIR R4: the patient, conditions, medications, observations and reports. FHIR stays FHIR, as nodes and relationships. ▸ Then OMOP, for research. It is not a copy: one script computes it from the same FHIR nodes. ▸ And at the bottom, the terminologies: SNOMED, ICD-10, RxNorm and LOINC. Every clinical node points to its code. ▸ Follow one lab value: the patient, the observation, its LOINC code, and the OMOP measurement that shares that very code. The code the phone chose is the code the researcher's question finds. The AI answers only from what this graph holds: no code, no answer.

What we found · why refusing matters

Four findings from coding real sheets to LOINC

The unit selects the code

Same label, two units: two measurements.

Refusing is a feature

A wrong code is worse than no code.

LOINC names tests, not organisms

57 stool taxa: NCBI Taxonomy instead.

Provenance must be first-class

A transcription marked final is the failure that matters.

8:15. These came out of scanning my own sheets and the tests that grew around each mistake. First: the same label in two units is two measurements; trusting the label alone put wrong codes on real values until the rule was made absolute. Second: both LOINC codes for RDW-SD are deprecated, so the value is carried unmatched rather than mis-coded. That one is my favourite: the honest answer was to refuse. Third: a stool report's 57 organisms have no LOINC term and never will, so NCBI Taxonomy names them. Fourth: final or preliminary is decided by the document, not by its file extension.

What we give back · five asks

Five asks to make a person's own lab result first-class in FHIR

  4. A citizen-upload profile in the EEHRxF laboratory result.Today: PDF plus bundle for the GP, preliminary where transcribed.
  5. FHIR-to-OMOP conventions for the uncoded case.Today: concept 0, the code or label in the source value.
9:15. These are asks, not complaints. Each is a place where we had to decide alone and would rather have decided with you, and each has a concrete case in the app on the right: the profile screen explains why a visceral-fat mass leaves without a code. The first and the fourth decide whether a person's own scanned result can ever be trusted downstream.
