Why I built this

I have a cardiovascular risk profile, and my results arrive on paper

The person

My results come from my doctor, from laboratories, and from the medical studies I take part in. As PDF, or on paper. Nothing pushes them into my patient record: only the provider who ordered a test may write to it, and a study is not treatment.

The researchers

I talk to many of them. They want exactly the kind of data I hold, across many people, under a permit from an access body. They cannot get it from me in a usable form, and they cannot get it across institutions at all.

The builder

Five years building and operating dataspaces, most recently the automotive supply chain's operating company. So I built the two halves: an iPhone app that holds my own record, and a dataspace that serves the researcher. Both on FHIR.

Stored once, in the cloud

Everything lands in one FHIR-based knowledge graph, five layers, every clinical node coded

A Neo4j graph on Azure Container Apps, persistent on Azure Files. FHIR R4 comes in from a hospital's server or from the phone's bundle and stays FHIR: Patient, Condition, Observation, MedicationRequest as nodes and relationships.

The FHIR-to-OMOP transform is one Cypher script over the same graph, so a person's Observation and its OMOP Measurement share the LOINC code node they are both coded by.

127 synthetic patients, more than 5,300 nodes. The plain-language query layer answers only from what the graph holds. No code, no answer.

What we found

Four findings from coding real sheets to FHIR and LOINC

The unit selects the code

The same label in two units is two measurements. Trusting the label alone put wrong codes on real values until the rule was made absolute.

Refusing is a feature

Both LOINC codes for RDW-SD are deprecated, so the value is carried unmatched rather than mis-coded. A wrong code is worse than no code.

LOINC names tests, not organisms

A stool report's 57 taxa have no LOINC term and never will. NCBI Taxonomy names them; the abundance stays a text code with the reason attached.

Provenance must be first-class

Final versus preliminary, and the page and line, decided by the document and not its file extension. Marking a transcription final is the failure that matters.

8:30. These came out of scanning my own sheets and the tests that grew around each mistake. The deprecated-code case is my favourite: the honest answer was to refuse.

What we need from the FHIR community

Five things that would make a person's own lab result first-class in FHIR

  1. An agreed extension for transcribed observations. Source kind, source line, page and box, recogniser confidence. We define ours; a shared one would let any receiver treat a scanned value with the right caution.
  2. A pattern for microbiome relative abundance. A text-only code with a data-absent-reason and a component carrying the NCBI Taxonomy entry under LOINC 41852-5. Is that the shape you want?
  3. LOINC terms consumer devices need. Visceral fat as a mass, the extracellular-to-total water ratio, remnant cholesterol, the triglyceride-to-HDL ratio.
  4. A citizen-upload profile in the EEHRxF laboratory result. What a person-submitted, possibly transcribed result must carry so a record system and a GP can read it with its provenance intact.
  5. FHIR-to-OMOP conventions for the uncoded case. Concept id 0 with the original code or label in the source value, mapped where the vocabulary lives.
9:30. These are asks, not complaints. Each is a place where we had to decide alone and would rather have decided with you. The first and the fourth decide whether a person's own scanned result can ever be trusted downstream.
