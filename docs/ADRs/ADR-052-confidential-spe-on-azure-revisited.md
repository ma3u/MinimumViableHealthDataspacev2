# ADR-052: The confidential secure processing environment, revisited against Azure and the vendors of October 2026

**Status:** Proposed
**Date:** 2026-10-04
**Relates to:** [ADR-037](ADR-037-secure-processing-environment-confidential-computing.md), [ADR-012](ADR-012-azure-container-apps.md), [ADR-042](ADR-042-off-hours-scaledown-current-state.md)
**Revisits:** the implementation choice of ADR-037 (Contrast as the concrete product). The pattern ADR-037 decided, confidential containers with remote attestation, stands.
**Tracks:** [#481](https://github.com/ma3u/MinimumViableHealthDataspacev2/issues/481), [#27](https://github.com/ma3u/MinimumViableHealthDataspacev2/issues/27)

## Context

ADR-037 (September 2026) decided that the secure processing environment of
Art. 73 is modelled on confidential containers with remote attestation, and
named Contrast from Edgeless Systems as the implementation, on the strength of
its use in the German ePA. Phase 1, the honest model with "Simulated
attestation", shipped. Phase 2, a real attestation, did not.

Three facts changed between then and now, checked on 3 and 4 October 2026:

1. **Azure Container Apps has confidential compute.** A DC-series dedicated
   workload profile (DC4 to DC96) on AMD SEV-SNP confidential VMs; preview in
   February 2026, announced generally available at Build 2026. It is offered in
   **UAE North only**, and it works at **VM level**: no attestation report
   reaches the app and there is no per-container execution policy. The hub's
   region is West Europe.
2. **Contrast moved.** Its documentation now ships a bare-metal cluster setup
   only; the AKS how-to existed through docs 1.6, and `AKS-CLH-SNP` remains in
   the code's platform model. Its licence is the Business Source License with
   **no additional use grant**, converting to AGPL-3.0 four years after each
   minor release. Constellation, the predecessor, was archived on 22 January 2026.
3. **The open-source route matured.** AKS confidential containers (Kata
   Confidential Containers, `KataCcIsolation`) give per-pod SEV-SNP isolation
   with a hardware report that covers image layers and runtime configuration,
   a policy generated by the open-source `genpolicy`, and verification through
   Azure Attestation. Kata and Confidential Containers are Apache-2.0. The
   feature is in preview, which the project accepts for the demonstrator
   (4 October 2026).

The regulation did not change. Art. 73(1)(b) asks for state-of-the-art
technical and organisational measures, Art. 73(2) forbids row-level data from
leaving, and Art. 73(5) has the Commission define the technical requirements by
26 March 2027. The TEHDAS2 specification for access bodies (February 2026)
prescribes no technology. Confidential computing is not mandated; it is what
the German ePA uses to answer the operator question, and it is what this hub
already claims.

## Decision

1. **Phase 2a is built vendor-free on AKS confidential containers.** An AKS
   cluster in `rg-mvhd-dev` with one `KataCcIsolation` node pool
   (`Standard_DC4as_cc_v5`, Azure Linux) runs the analysis workload and a
   Neo4j holding only the permitted dataset, images pinned by digest, policy
   from `genpolicy`, data on an Azure Disk persistent volume. The HDAB
   persona's "verify environment" fetches the SEV-SNP report through Azure
   Attestation and compares the policy hash with the one recorded on the data
   permit. `SPESession.simulated` becomes false for that session only. A
   failed verification blocks the run.
2. **Contrast is no longer the named implementation.** It becomes one of two
   candidates for phase 2b, the deployment-level manifest that lets an access
   body attest a whole environment from outside, next to Enclaive. Phase 2b
   starts only if phase 2a leaves a gap the manifest closes, and only after a
   written licence answer: the live demonstrator is production use under
   Contrast's BSL.
3. **Azure Container Apps stays the home of everything else**, and becomes a
   candidate for the SPE's VM-level option the day a DC profile is offered in
   an EU region. A region request is filed now. Nothing moves to UAE North.
4. **Timing: deferred.** Decided 4 October 2026: the hub does not switch to
   confidential compute yet. No spike, no cluster, no region request. Phase 2a
   starts when one of three things happens: an access-body demonstration is
   scheduled (#27), a partner conversation reaches data governance (#478), or
   the Art. 73(5) implementing acts name a requirement (due 26 March 2027).
   Until then the SPE stays labelled "Simulated attestation" (ADR-037 phase
   1), which is the honest state.

## Consequences

- The Apache-2.0 repository depends only on Apache-2.0 components and Azure
  services. No vendor licence is needed for phase 2a.
- The attestation story is per pod, not per deployment. What the HDAB verifies
  is "this image and this configuration ran in a SEV-SNP VM", matched to the
  permit by the policy hash the hub records at approval. The manifest and
  `contrast verify` experience of ADR-037's table is what phase 2b would add.
- Nothing runs or costs anything until the trigger above. When it does: a
  second runtime (AKS beside ACA), two scale-down schedules, one more thing to
  keep healthy before a demo, roughly $150 to $300 a month for one node while
  it runs. Everything that does not touch row-level data stays on ACA.
- Preview constraints apply and are accepted: memory is the sum of container
  limits plus 2 GB, `requests` are ignored, IOPS on Azure Files are lower, and
  `exec` into a pod needs a policy change that the attestation then measures.
- ADR-037's phase 3, the permit becoming the manifest, is deferred with phase
  2b. Until then the permit carries the policy hash and the hub compares it.
