# Software bills of materials

One CycloneDX file per deployable part ([1.7](https://cyclonedx.org/docs/1.7/json/) for the hub and the
three services, [1.5](https://cyclonedx.org/docs/1.5/json/) for the iPhone app, as each file's `specVersion`
says), generated by
[`scripts/security/generate-sbom.sh`](../../scripts/security/generate-sbom.sh) ([syft](https://github.com/anchore/syft/releases/tag/v1.51.1) over the lockfiles, no `node_modules`
needed) and committed so a reviewer reads the bill next to the code it
describes. `--check` fails when a committed bill no longer matches the
lockfiles, which is how a dependency change that forgot the bill is caught.

| File                                                       | What                                                                                               | Source of truth                                                                                                 |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| [`ui.cdx.json`](ui.cdx.json)                               | the Next.js hub, [`ui/`](../../ui)                                                                 | [`ui/package-lock.json`](../../ui/package-lock.json)                                                            |
| [`neo4j-proxy.cdx.json`](neo4j-proxy.cdx.json)             | the FHIR, OMOP and NLQ bridge                                                                      | [`services/neo4j-proxy/package-lock.json`](../../services/neo4j-proxy/package-lock.json)                        |
| [`epa-ingest.cdx.json`](epa-ingest.cdx.json)               | the ePA ingest CLI and analyte dictionary                                                          | [`services/epa-ingest/package-lock.json`](../../services/epa-ingest/package-lock.json)                          |
| [`claude-federation.cdx.json`](claude-federation.cdx.json) | the hosted explanation service ([ADR-034](../ADRs/ADR-034-claude-workload-identity-federation.md)) | [`services/claude-federation/package-lock.json`](../../services/claude-federation/package-lock.json)            |
| [`klarbefund-ios.cdx.json`](klarbefund-ios.cdx.json)       | the iPhone app, [`clients/ios`](../../clients/ios)                                                 | [`Package.swift`](../../clients/ios/Package.swift), [`project.yml`](../../clients/ios/project.yml), the imports |

The iPhone app declares no third-party package, so its bill lists the Apple
frameworks it links (from the `import` statements, by
[`scripts/security/generate-ios-sbom.py`](../../scripts/security/generate-ios-sbom.py)) and says so in its metadata. That is
the checkable form of the claim in
[`docs/klarbefund/self-assessment.md`](../klarbefund/self-assessment.md)
(BSI [TR-03161](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/Publications/TechGuidelines/TR03161/TR-03161-1.pdf?__blob=publicationFile&v=2) O.TrdP).

Vulnerabilities against these bills: [`scripts/security/scan-repo.sh`](../../scripts/security/scan-repo.sh) runs
[grype](https://github.com/anchore/grype/releases/tag/v0.118.0) over them locally; [`.github/workflows/security-scan.yml`](../../.github/workflows/security-scan.yml) does the same
in CI for the hub and uploads the result to the [Security tab](https://docs.github.com/en/code-security/code-scanning/introduction-to-code-scanning/about-code-scanning). Container
images are scanned separately, with [trivy](https://github.com/aquasecurity/trivy/releases/tag/v0.74.0), in the same workflow.
