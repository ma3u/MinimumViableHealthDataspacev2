# Klarbefund: self-assessment

Data protection, security and regulatory status of the Klarbefund iPhone app,
assessed by the project itself against the code in [`clients/ios/`](../../clients/ios/) as of
2026-10-15. **This is a self-assessment, not a certification, an audit or a
legal opinion.** Every "met" below points to the code or test that shows it;
anything not shown is marked open. Accuracy evidence is in
[`evidence.md`](evidence.md); running it on a Mac in [`run-on-mac.md`](run-on-mac.md).
The code references below were last checked against the sources on 2026-10-15,
the same day the evidence was last produced (see the run record in
[`evidence.md`](evidence.md#run-record)).

Status values: **met** (implemented and shown in code or tests), **partly**
(implemented in part, or shown only by design), **open** (not done), **n/a**
(does not apply to this app).

## What would close the open items

Done on 2026-10-15, by the project itself (see
[`docs/security/security-test-report-2026-10-15.md`](../security/security-test-report-2026-10-15.md)):
the threat model, the SBOM, a configuration test suite, and a self-conducted
security test with CodeQL, Semgrep, grype, trivy, gitleaks and anonymous
black-box checks of the hub. Still open:

1. Written intended-purpose statement and [MDCG 2019-11](https://health.ec.europa.eu/document/download/b45335c5-1679-4c71-a91c-fc7a4d37f12b_en) qualification, with an
   external opinion on the trends colouring.
2. Hosted explanation service: name the operator as controller or processor,
   sign the processor agreement with Azure (EU data zone, the default), and for
   the opt-in Anthropic option document the transfer basis or switch it off.
3. DPIA template and data-flow diagram for an operator.
4. An **independent** penetration test (a release build on a device, the
   hub as each role in office hours), and the requirement-level TR-03161
   part 1 gap list against the official PDF. The self-conducted test says
   what such a test would add.
5. Done 2026-10-15 ([ADR-060](../ADRs/ADR-060-the-app-locks-with-face-id-and-answers-pinning-and-jailbreak-detection.md)): the app lock is implemented, on by default;
   certificate pinning and jailbreak detection are declined with written
   reasons. Remaining for a laboratory: judge those reasons.
