# Security test report, 2026-10-15

A self-conducted security test of the Klarbefund app and the demo hub, by
the project, with the tools the repository can run: static analysis,
dependency and container scanning, secret scanning, configuration tests
and anonymous black-box checks of the live hub. **It is not an independent
penetration test.** What such a test would add is listed at the end. Every
number here is reproducible with the commands given; the raw reports of this
run are not committed (they carry paths), the scripts are.

## What an independent test would add

This report is the project testing itself with deterministic tools. It
does not replace, and the self-assessment does not claim, an independent
penetration test. Such a test, by a BSI-recognised laboratory or a
contracted tester, would add:

1. **A release build on a device**: runtime inspection of the Keychain
   items, the sealed store and the file protection classes with the phone
   locked and unlocked; the cable test repeated by someone else.
2. **Authenticated black-box testing of the hub** as each of the seven
   roles, in office hours: horizontal access between patients (`refuseForeignRecord`), the
   app token's scope, rate limits under load, the App Attest verification
   with a replayed or forged attestation.
3. **The TR-03161 part 1 requirement list**, item by item against the
   official document, which this project assesses only at the level of its
   objective groups (`docs/klarbefund/self-assessment.md`).
4. **Keycloak and EDC configuration review** beyond what the public
   endpoints show.

Until then, the status in the self-assessment reads "tested by the
project, independent test open", and this document is the evidence for
the first half of that sentence.
