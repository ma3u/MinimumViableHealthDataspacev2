# BSI C5 gap analysis: the EHDS Integration Hub

**Standard**: BSI Cloud Computing Compliance Criteria Catalogue, [C5:2020](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/CloudComputing/ComplianceControlsCatalogue/2020/C5_2020.pdf?__blob=publicationFile&v=5) ([BSI page](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_AktuelleVersion/C5_AktuelleVersion_node.html)). The BSI recommends [C5:2026](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_2025/C5_2025_node.html) for test periods ending on or after 1 June 2027; this analysis has not been moved to it yet.
**Relevance**: No article of [Regulation (EU) 2025/327](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng) names C5. [Art. 73(1)](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.001) sets the security measures of the secure processing environment, [Art. 73(3)](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.003) requires regular audits of it, including by third parties, and [Art. 73(5)](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.005) leaves the detailed requirements to implementing acts due by 26 March 2027. C5 is what a public buyer in Germany asks of the cloud underneath ([operational guideline, section 3](operational-guideline.md#3-the-bsi-standards-part-by-part)); this analysis uses it as the yardstick for the hub. Earlier versions cited "Art. 50(6)", a number from the 2022 proposal; adopted [Art. 50](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#art_50) is "Applicability to health data holders" ([numbering](../ehds-article-numbering.md)).
**Scope**: Demo/MVP assessment. A real C5 report needs an accredited auditor.

Every criterion id links to its page in the C5:2020 PDF, and its title is the catalogue's. Versions up to 2026-03-28 used ids that do not exist in C5:2020 (CCM, IAM, DIP, LOG, INS) and gave OIS, DEV and COS ids titles they do not have; the table at the end lists each change.

### Code-level measures with no criterion of their own

C5:2020 asks for a secure development policy (DEV-01) and for vulnerability identification including static analysis (PSS-02); it has no criterion for the following measures, which are the hub's evidence for both:

| Measure                              | Demo Status | Where the hub stands                                                                                                                                           |
| ------------------------------------ | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Parameterised queries                | ✅          | Parameterised Cypher, never string-interpolated ([`api-conventions.md`](../../.claude/rules/api-conventions.md#query-patterns))                                |
| Output encoding and a content policy | ✅          | React escapes output; a per-request nonce CSP with `strict-dynamic` ([`middleware.ts`](../../ui/src/middleware.ts#L88-L95))                                    |
| No credentials in the code           | ✅          | Environment variables and Key Vault references ([ADR-036](../ADRs/ADR-036-operator-secrets-in-key-vault.md)); gitleaks as under PSS-02                         |
| Data minimisation                    | ✅          | FHIR routes return the requested fields only; a GDPR principle ([Art. 5(1)(c)](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng#005.001)), not a C5 criterion |
