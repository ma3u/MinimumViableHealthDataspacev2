# BSI C5-gapanalyse: EHDS-integratiehub

**Norm**: BSI Cloud Computing Compliance Criteria Catalogue, [C5:2020](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/CloudComputing/ComplianceControlsCatalogue/2020/C5_2020.pdf?__blob=publicationFile&v=5) ([BSI-pagina](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_AktuelleVersion/C5_AktuelleVersion_node.html)). Voor testperiodes die op of na 1 juni 2027 eindigen, raadt het BSI [C5:2026](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_2025/C5_2025_node.html) aan; deze analyse is daar nog niet op overgezet.
**Relevantie**: Geen artikel van [Verordening (EU) 2025/327](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng) noemt C5. [Art. 73, lid 1](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.001), legt de beveiligingsmaatregelen van de beveiligde verwerkingsomgeving vast, [art. 73, lid 3](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.003), vereist regelmatige audits, ook door derden, en [art. 73, lid 5](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.005), laat de gedetailleerde eisen over aan uitvoeringshandelingen die uiterlijk 26 maart 2027 komen. C5 is wat een overheidsopdrachtgever in Duitsland van de onderliggende cloud vraagt ([operationele richtlijn, sectie 3](operational-guideline.md#3-de-bsi-normen-onderdeel-voor-onderdeel)); deze analyse gebruikt het als maatstaf voor de hub. Eerdere versies noemden "art. 50, lid 6", een nummer uit het voorstel van 2022; het vastgestelde [art. 50](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#art_50) is "Toepasselijkheid op houders van gezondheidsgegevens" ([nummering](../ehds-article-numbering.md)).
**Reikwijdte**: Beoordeling van demo/MVP. Een echt C5-rapport vereist een geaccrediteerde auditor.

Elk criteriumnummer verwijst naar zijn pagina in de pdf van C5:2020, en de titel is die van de catalogus, geciteerd uit de Engelse versie. De versies tot 2026-03-28 gebruikten nummers die in C5:2020 niet bestaan (CCM, IAM, DIP, LOG, INS) en gaven OIS-, DEV- en COS-nummers titels die ze niet hebben; de tabel aan het einde noemt elke wijziging.

### Maatregelen in de code zonder eigen criterium

C5:2020 vraagt een beleid voor veilige ontwikkeling (DEV-01) en het opsporen van kwetsbaarheden, inclusief statische analyse (PSS-02); voor de volgende maatregelen heeft het geen eigen criterium, ze zijn het bewijs van de hub voor beide:

| Maatregel                            | Demostatus | Waar de hub staat                                                                                                                                                             |
| ------------------------------------ | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Geparametriseerde queries            | ✅         | Geparametriseerde Cypher, nooit via stringinterpolatie ([`api-conventions.md`](../../.claude/rules/api-conventions.md#query-patterns))                                        |
| Output-encoding en een contentbeleid | ✅         | React escapet de output; een CSP met nonce per verzoek en `strict-dynamic` ([`middleware.ts`](../../ui/src/middleware.ts#L88-L95))                                            |
| Geen inloggegevens in de code        | ✅         | Omgevingsvariabelen en Key Vault-referenties ([ADR-036](../ADRs/ADR-036-operator-secrets-in-key-vault.md)); gitleaks zoals onder PSS-02                                       |
| Gegevensminimalisatie                | ✅         | FHIR-routes geven alleen de gevraagde velden terug; een AVG-beginsel ([art. 5, lid 1, punt c)](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng#005.001)), geen C5-criterium |
