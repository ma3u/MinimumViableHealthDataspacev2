# Analyse des écarts BSI C5 : hub d’intégration EEDS

**Référentiel** : catalogue de critères de conformité du cloud computing du BSI, [C5:2020](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/CloudComputing/ComplianceControlsCatalogue/2020/C5_2020.pdf?__blob=publicationFile&v=5) ([page du BSI](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_AktuelleVersion/C5_AktuelleVersion_node.html)). Pour les périodes de test se terminant le 1er juin 2027 ou après, le BSI recommande le [C5:2026](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_2025/C5_2025_node.html) ; cette analyse n’y est pas encore passée.
**Pertinence** : aucun article du [règlement (UE) 2025/327](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng) ne nomme le C5. L’[art. 73, paragraphe 1](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.001), fixe les mesures de sécurité de l’environnement de traitement sécurisé, l’[art. 73, paragraphe 3](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.003), exige des audits réguliers, y compris par des tiers, et l’[art. 73, paragraphe 5](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.005), renvoie les exigences détaillées à des actes d’exécution attendus pour le 26 mars 2027. Le C5 est ce qu’un acheteur public en Allemagne demande du cloud sous-jacent ([guide d’exploitation, section 3](operational-guideline.md#3-les-normes-du-bsi-partie-par-partie)) ; cette analyse le prend comme étalon pour le hub. Les versions antérieures citaient « art. 50(6) », un numéro de la proposition de 2022 ; l’[art. 50](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#art_50) adopté est « Applicabilité aux détenteurs de données de santé » ([numérotation](../ehds-article-numbering.md)).
**Périmètre** : évaluation de démonstration/MVP. Un véritable rapport C5 requiert un auditeur accrédité.

Chaque numéro de critère renvoie à sa page dans le PDF du C5:2020, et son titre est celui du catalogue, cité dans la version anglaise. Les versions jusqu’au 2026-03-28 utilisaient des numéros qui n’existent pas dans le C5:2020 (CCM, IAM, DIP, LOG, INS) et donnaient aux numéros OIS, DEV et COS des titres qu’ils n’ont pas ; le tableau final liste chaque changement.

### Mesures dans le code sans critère propre

Le C5:2020 demande une politique de développement sécurisé (DEV-01) et l’identification des vulnérabilités, analyse statique comprise (PSS-02) ; il n’a pas de critère propre pour les mesures suivantes, qui sont les preuves du hub pour les deux :

| Mesure                                       | Statut démo | Où en est le hub                                                                                                                                                                            |
| -------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Requêtes paramétrées                         | ✅          | Cypher paramétré, jamais par interpolation de chaînes ([`api-conventions.md`](../../.claude/rules/api-conventions.md#query-patterns))                                                       |
| Encodage des sorties et politique de contenu | ✅          | React échappe la sortie ; une CSP avec nonce par requête et `strict-dynamic` ([`middleware.ts`](../../ui/src/middleware.ts#L88-L95))                                                        |
| Aucun identifiant dans le code               | ✅          | Variables d’environnement et références Key Vault ([ADR-036](../ADRs/ADR-036-operator-secrets-in-key-vault.md)) ; gitleaks comme sous PSS-02                                                |
| Minimisation des données                     | ✅          | Les routes FHIR ne renvoient que les champs demandés ; un principe du RGPD ([art. 5, paragraphe 1, point c)](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng#005.001)), pas un critère C5 |
