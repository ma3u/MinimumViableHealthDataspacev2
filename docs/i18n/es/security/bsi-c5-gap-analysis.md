# Análisis de brechas BSI C5: hub de integración EEDS

**Norma**: catálogo de criterios de cumplimiento para la computación en la nube del BSI, [C5:2020](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/CloudComputing/ComplianceControlsCatalogue/2020/C5_2020.pdf?__blob=publicationFile&v=5) ([página del BSI](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_AktuelleVersion/C5_AktuelleVersion_node.html)). Para periodos de prueba que terminen el 1 de junio de 2027 o después, el BSI recomienda el [C5:2026](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Informationen-und-Empfehlungen/Empfehlungen-nach-Angriffszielen/Cloud-Computing/Kriterienkatalog-C5/C5_2025/C5_2025_node.html); este análisis aún no se ha pasado a él.
**Pertinencia**: ningún artículo del [Reglamento (UE) 2025/327](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng) menciona C5. El [art. 73, apartado 1](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.001), fija las medidas de seguridad del entorno de tratamiento seguro, el [art. 73, apartado 3](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.003), exige auditorías periódicas, también por terceros, y el [art. 73, apartado 5](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#073.005), remite los requisitos detallados a actos de ejecución previstos para el 26 de marzo de 2027. C5 es lo que un comprador público en Alemania pide a la nube subyacente ([guía operativa, sección 3](operational-guideline.md#3-las-normas-del-bsi-parte-por-parte)); este análisis lo usa como referencia para el hub. Las versiones anteriores citaban el «art. 50, apartado 6», un número de la propuesta de 2022; el [art. 50](https://eur-lex.europa.eu/eli/reg/2025/327/oj/eng#art_50) adoptado es «Aplicabilidad a los tenedores de datos de salud» ([numeración](../ehds-article-numbering.md)).
**Alcance**: evaluación de demostración/MVP. Un informe C5 real requiere un auditor acreditado.

Cada número de criterio enlaza con su página en el PDF de C5:2020, y su título es el del catálogo, citado de la versión inglesa. Las versiones hasta el 2026-03-28 usaban números que no existen en C5:2020 (CCM, IAM, DIP, LOG, INS) y daban a los números OIS, DEV y COS títulos que no tienen; la tabla final enumera cada cambio.

### Medidas en el código sin criterio propio

C5:2020 pide una política de desarrollo seguro (DEV-01) y la identificación de vulnerabilidades, incluido el análisis estático (PSS-02); no tiene criterio propio para las medidas siguientes, que son la evidencia del hub para ambos:

| Medida                                                | Estado en la demo | Situación del hub                                                                                                                                                                             |
| ----------------------------------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Consultas parametrizadas                              | ✅                | Cypher parametrizado, nunca mediante interpolación de cadenas ([`api-conventions.md`](../../.claude/rules/api-conventions.md#query-patterns))                                                 |
| Codificación de la salida y una política de contenido | ✅                | React escapa la salida; una CSP con nonce por solicitud y `strict-dynamic` ([`middleware.ts`](../../ui/src/middleware.ts#L88-L95))                                                            |
| Ninguna credencial en el código                       | ✅                | Variables de entorno y referencias de Key Vault ([ADR-036](../ADRs/ADR-036-operator-secrets-in-key-vault.md)); gitleaks como en PSS-02                                                        |
| Minimización de datos                                 | ✅                | Las rutas FHIR solo devuelven los campos solicitados; un principio del RGPD ([art. 5, apartado 1, letra c)](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng#005.001)), no un criterio de C5 |
