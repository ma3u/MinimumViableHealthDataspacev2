# `services/eudi-wallet-backend` — overlay for the German national wallet backend

This directory does **not** contain the wallet backend. It contains the parts the
published mirror does not ship, so that the mirror can be built and run.

Upstream: [`german-national-wallet/de-eudi-wallet-backend`](https://github.com/german-national-wallet/de-eudi-wallet-backend),
Apache-2.0, one-way read-only mirror. It publishes `src/main/kotlin` and
`gradle/libs.versions.toml` — no build files, no resources, no schema. Its README
says a configuration file is "coming".

| Path                         | What it is                                                                        |
| ---------------------------- | --------------------------------------------------------------------------------- |
| `overlay/*.gradle.kts`       | The build. Dependencies are the catalogue entries the published source imports.   |
| `overlay/src/main/kotlin`    | OpenAPI doc constants the four `*Api.kt` reference but the mirror never declares. |
| `overlay/src/main/resources` | `application.yaml`, the Flyway schema, the Android revocation list stub.          |
| `Dockerfile`                 | Two-stage: clones the mirror and builds it, so the image needs no hand-built jar. |
| `certs/`                     | Generated by `scripts/eudi/gen-dev-certs.sh`. Git-ignored; throwaway dev anchors. |

The mirror itself is cloned to `vendor/eudi-wallet-backend/` (git-ignored) by
`scripts/eudi/build-backend.sh`, which copies only the two `.kts` files into it —
everything else is read from this overlay in place, so the checkout stays verbatim
(ADR-005).

Run it: `docker compose -f docker-compose.yml -f docker-compose.eudi.yml up -d`.
Full detail, including the five distinct reasons a naive build fails and what the
`build-docs` profile does and does not give you, is in
[`docs/knowledge/runbooks/eudi-wallet-backend-local.md`](../../docs/knowledge/runbooks/eudi-wallet-backend-local.md).
